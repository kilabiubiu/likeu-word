# LikeU 词根背单词 —— 微信云托管部署手册

> 适用版本：`likeu-backend`（Spring Boot 2.7 / Java 8）+ `likeu-miniapp`（原生小程序）
> 已按「微信云托管」的规范完成适配：小程序走 `wx.cloud.callContainer` 内网直连，**不需要域名、不需要 ICP 备案、不需要配置服务器域名**；后端已去掉 Redis 依赖。

---

## 0. 先看清楚：现在的调用链长什么样

```
微信开发者工具（develop）
   └─ wx.request  →  http://localhost:8080/api/...        （本机后端，方便断点调试）

体验版 / 正式版（trial / release）
   └─ wx.cloud.callContainer（微信内网，无需域名）
         ├─ 请求头自动带 X-WX-OPENID  →  后端直接识别用户，无需 wx.login / code2Session
         └─ 直达云托管服务 likeu-word:8080  →  /api/...  →  云托管 MySQL（内网）
```

三个必须记住的硬性约束（都是官方规范，踩了就上不去）：

| 约束 | 说明 |
| --- | --- |
| 默认公网域名不能给正式版用 | 官方明确：默认公网域名仅用于接口测试，**小程序后台无法把它配成 request 合法域名**。所以正式版必须走 `callContainer`（本方案）或自备已备案域名。 |
| 不能部署有状态服务 | 云托管明确不支持部署数据库 / Redis。本项目已把缓存改为进程内、登录态改为无状态 JWT + `X-WX-OPENID`，**不需要再买 Redis**。 |
| 一个服务只能监听一个端口 | 后端固定 `8080`（`server.port`），控制台「端口」也要填 8080。 |

## 1. 开工前准备

| 需要的东西 | 在哪拿 |
| --- | --- |
| 小程序 AppID | `wx6a8da5d3ab7795a0`（已在 `likeu-miniapp/project.config.json`）**云托管环境必须建在这个 AppID 名下** |
| 小程序 AppSecret | 小程序后台 →「开发管理 → 开发设置 → AppSecret」（只需生成一次并保管好） |
| 微信云托管控制台 | <https://cloud.weixin.qq.com/cloudrun> ，用小程序管理员扫码登录 |
| 可直传的代码包 | 仓库根目录 `dist/likeu-backend-cloudrun.zip`（约 250KB，限制 2MiB） |
| JWT 密钥 | 自己生成一段 32 位以上随机串（后文有生成命令） |

> 计费：云托管容器按 CPU/内存用量、MySQL 按 CCU + 存储计费，均按量。建议先在「费用中心」看看有没有代金券。**副本数最小值设为 0 会省钱，但会有 0→1 的冷启动（首次请求慢几秒）。**

本地没有装 Docker 也没关系：**镜像由云托管在云端构建**，你只需要上传源码。本地 `mvn -DskipTests package` 能过即可（当前已验证通过）。

## 2. 第 1 步：开通云托管环境

1. 打开 <https://cloud.weixin.qq.com/cloudrun>，扫码选择你的小程序，进入控制台。
2. 首次进入会引导「创建环境」（若模板引导里让你一键部署示例，选择跳过/自定义部署）。环境 ID 形如 `prod-xxxxxxxx`，**记下它**，小程序端要填。
3. 环境创建需要几分钟，等状态变成「正常」。

---

## 3. 第 2 步：开通 MySQL 并建库

1. 控制台左侧「MySQL」→ 开通，选择 **MySQL 8.0**（或 5.7，选定后不可改），设置一个强密码并保存好（云托管不存密码，忘了只能重置）。
2. 开通后进入「数据库管理」，会跳到腾讯云 DMS 网页版，输入密码登录。
3. 在 DMS 里建库（云托管 MySQL 只自带 3 个系统库，业务库要自己建）：

```sql
CREATE DATABASE IF NOT EXISTS likeu_word
  DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;
```

4. 回到 MySQL 页面，记下 **内网地址**（形如 `10.0.0.12:3306`）——一会儿要拆成 `MYSQL_HOST` 和 `MYSQL_PORT`。**不要开外网地址**（有安全风险，也没必要）。
5. 建议把「自动暂停」**关闭**：开启时连续 10 分钟无请求会暂停数据库，之后第一个请求可能返回
   `CynosDB serverless instance is resuming, please try connecting again.` 造成偶发 500。关闭后按最小算力（0.25 CCU）持续计费，成本仍然很低。

建表脚本已经随代码包一起打进镜像了，不用手动跑（见第 5 步的 `DB_INIT_MODE`）；如果你更习惯手动执行，也可以用 DMS 直接跑
`likeu-backend/src/main/resources/data/schema.sql`。

---

## 4. 第 3 步：创建服务

控制台「服务管理 → 新建服务」：

| 配置项 | 填什么 |
| --- | --- |
| 服务名称 | `likeu-word`（要和 `likeu-miniapp/utils/config.js` 里的 `CLOUD_SERVICE_NAME` 一致） |
| 端口 | `8080` |
| 部署方式 | 首推「手动上传代码包」（见下方说明），后续可换成 Git 仓库流水线 |
| 目标目录 | 上传 `dist/likeu-backend-cloudrun.zip` 时**留空**（包内已是 `Dockerfile` / `pom.xml` / `src` 平铺） |
| Dockerfile | `Dockerfile` |
| 规格 | 0.5 核 1GB 起步即可，副本数 0~2（或 1~2 求稳） |

**方式一：手动上传代码包（最快，不需要任何 Git 托管）**

1. 取仓库根目录的 `dist/likeu-backend-cloudrun.zip`。
2. 控制台「部署发布」→ 选择代码 → 手动上传代码包 → 上传该 zip → 端口 8080 → Dockerfile 填 `Dockerfile` → 目标目录留空。
3. 首次发布还会让你填环境变量（见第 5 步，可以先随便填后改，但**建议一次填对**）。

**方式二：绑定 Git 仓库 + 流水线（推荐长期迭代用）**

1. 代码已经托管在 `git@github.com:kilabiubiu/likeu-word.git`（分支 `main`）。
2. 「服务设置 → 流水线」绑定该 GitHub 仓库，关键三项：
   - 目标目录：`likeu-backend`（仓库根目录下就是它）
   - Dockerfile：`likeu-backend/Dockerfile`（或目标目录设为 `likeu-backend` 后填 `Dockerfile`）
   - 端口：`8080`
3. 之后每次 `git push` 就能在控制台一键用流水线构建发布。国内访问 GitHub 构建偶尔慢，也可以改用 Gitee 镜像仓库。

> 代码包体积：云托管手动上传限制 **2 MiB**。本包约 250KB（只含 `Dockerfile`/`pom.xml`/`src`，已排除 `target`、`logs`），完全够用。**不要把 `likeu-miniapp/node_modules` 打进去。**

## 5. 第 4 步：配置环境变量（最容易漏的一步）

控制台「服务设置 → 基本信息 → 环境变量」。后端启动时有强制校验：`JWT_SECRET`、`WX_MINI_APPID`、`WX_MINI_SECRET` 缺失或仍是示例值会直接**拒绝启动**（日志里会写明是哪个变量）。

| 变量名 | 必填 | 示例 / 说明 |
| --- | --- | --- |
| `JWT_SECRET` | ✅ | 随机 32 位以上字符串。生成：`powershell -c "[guid]::NewGuid().ToString('N') + [guid]::NewGuid().ToString('N')"` |
| `WX_MINI_APPID` | ✅ | `wx6a8da5d3ab7795a0` |
| `WX_MINI_SECRET` | ✅ | 该 AppID 后台的 AppSecret（小程序后台 →「开发管理 → 开发设置 → AppSecret」）。⚠️ 走 callContainer 时后端其实不会调用微信接口，这个值只是启动校验与本地 code2Session 兜底通道需要，**不要**把它发到聊天/工单里 |
| `MYSQL_HOST` | ✅ | MySQL 内网地址的 host 部分，如 `10.0.0.12` |
| `MYSQL_PORT` | ✅ | `3306` |
| `MYSQL_DATABASE` | ✅ | `likeu_word` |
| `MYSQL_USERNAME` | ✅ | `root`（或你在账号管理里新建的账号） |
| `MYSQL_PASSWORD` | ✅ | 开通 MySQL 时设置的密码 |
| `DB_INIT_MODE` | 首次 | 首次部署填 `always`（自动建表 + 灌演示词库），**建完改回 `never` 再发布一次** |
| `ADMIN_OPENIDS` | 可选 | 管理员 openid，逗号分隔；留空 = `/admin/**` 对所有人关闭 |
| `DB_POOL_MIN` / `DB_POOL_MAX` | 可选 | 建议 `1` / `5`，Serverless MySQL 不需要大连接池 |
| `CORS_ALLOWED_ORIGINS` | 可选 | 留空（小程序请求不受同源策略限制） |
| `DOC_ENABLED` | 可选 | 保持 `false`（生产不开放 Swagger） |

> ⚠️ **不再需要** `REDIS_*` 任何变量。若以前配过，请删掉，避免误导排查。
> MySQL 连接串里 `useSSL=false`、`serverTimezone=Asia/Shanghai` 都已在 `application.yml` 内置，无需额外配置。

## 6. 第 5 步：部署并发布

1. 「部署发布」→ 选择代码 → 发布。构建阶段会执行容器内 Maven 构建（首次约 5~10 分钟，之后有缓存会快很多）。
2. 构建成功 → 进入部署阶段，日志里应能看到：

```
启动配置校验通过
鉴权白名单: [/user/login, /favicon.ico, /error, /actuator/health]
Tomcat started on port(s): 8080 (http)
```

3. 若勾选了「灰度发布」，可以用 OpenID 白名单先自测，再点「灰度上线」逐步放量；没勾选则直接全量。
4. 首次发布若 `DB_INIT_MODE=always`，用 DMS 确认表已建好：`SHOW TABLES;` 应能看到 `t_user`、`t_word`、`t_root` 等。
   **确认后把 `DB_INIT_MODE` 改成 `never`，再发布一次**（否则每次重启都会重跑初始化脚本）。
5. 自检健康接口（用控制台「云端调试 / 登录实例 WebShell」）：

```bash
wget -qO- http://localhost:8080/api/actuator/health
# {"status":"UP"}
```

---

## 7. 第 6 步：关闭公网访问（**安全必做**）

服务设置里把「**公网访问**」关掉。

原因：后端信任请求头 `X-WX-OPENID` 作为用户身份（这是官方推荐的做法，openid 由微信网关在服务端注入）。**只有关闭公网访问，才能保证请求一定来自微信内网、该请求头无法被伪造**。关掉之后：
- 小程序 `callContainer` 调用完全不受影响（走内网，不计公网流量，天然免疫 DDoS）；
- 浏览器/curl 从外部访问不到服务（也就无法伪造 openid 读别人的数据）。

> 若确有外部调用需求（例如自建管理后台），请单独开一个服务或加一层带签名的网关，不要直接把本服务暴露到公网。

## 8. 第 7 步：小程序端配置与上传

1. 填环境 ID —— 打开 `likeu-miniapp/utils/config.js`：

```js
const CLOUD_ENV_ID = 'prod-xxxxxxxx';   // ← 第 1 步记下的云托管环境 ID
const CLOUD_SERVICE_NAME = 'likeu-word'; // 与服务名一致
```

2. 小程序后台 →「设置 → 功能设置 → 基础库最低版本」，设为 **2.23.0 或以上**（`wx.cloud.callContainer` 的硬要求）。
   - 「服务器域名」**什么都不用配**（不走公网域名，也就不需要备案）。
3. 开发者工具里：
   - 默认（`develop`）走 `http://localhost:8080/api`，本机起后端就能全流程调试；
   - 想在工具里直接验证云通道，把 `utils/config.js` 的 `FORCE_CLOUD_IN_DEVTOOLS` 改成 `true`（前提是工具里已开通/关联该云环境）。
4. 上传体验版（工具右上角「上传」）→ 真机验证 → 提交审核 → 发布。
5. 真机验证要点：登录、词书切换、学习/复习、收藏、我的统计、重置进度，逐项过一遍（清单见下一节）。

## 10. 生产词库数据怎么进库

| 方式 | 适用 | 做法 |
| --- | --- | --- |
| A. 应用自动初始化（最省事） | 首次部署、先用演示数据跑通 | `DB_INIT_MODE=always` 发布一次，会自动执行 `schema.sql` + `init_demo_data.sql`，然后改回 `never` |
| B. DMS 手工执行 SQL（推荐用于正式词库） | 自备词库 | DMS 里先跑 `schema.sql` 建表，再跑你自己的 `INSERT` 脚本（参考 `init_demo_data.sql` 的格式，可重复执行） |
| C. `/admin/import/*` JSON 接口 | 少量增量维护 | 需在 `ADMIN_OPENIDS` 配好你自己的 openid（登录一次后在 DMS 里 `SELECT openid FROM t_user;` 查）；因为公网已关闭，这个接口目前只能由小程序内调用——需要临时开公网用 curl 的话，**用完立刻关掉公网访问** |

> 缓存在进程内（每个实例一份）：导入基础数据后想立刻全局生效，重新发布一次版本（或控制台重启服务）即可，否则最迟等 TTL 到期（词书 24 小时、词根 1 小时、单词 2 小时）。

## 11. 日常迭代与回滚

- **改后端**：代码包方式 → 重新打 zip 上传发布；Git 流水线方式 → `git push` 后控制台执行流水线。建议勾「灰度发布」，用 OpenID 白名单自测再放量。
- **回滚**：控制台「部署发布 → 版本列表」选历史版本回退（只能回退到更早的版本）；每次发布都会留存版本与发布日志。
- **改小程序**：改完上传体验版 → 审核 → 发布。域名/备案这块永远不用管。
- **看日志**：控制台「服务日志」看 stdout（应用同时写文件，但容器不持久化，文件日志只用于实例内排查）。
- **只想临时改配置**：改环境变量会触发新版本，必须发布才生效。

## 13. 常见问题速查

| 现象 | 原因 / 处理 |
| --- | --- |
| 构建阶段失败 | 看构建日志；先确认本地 `mvn -DskipTests package` 通过。代码包 >2MiB 会被拒（本包 250KB） |
| 部署阶段失败，日志有 `配置项 xxx 未设置` | 环境变量漏填，按日志补 `JWT_SECRET` / `WX_MINI_*` 后重新发布 |
| 部署阶段失败，实例反复重启 | 端口不是 8080；或数据库内网地址写错（注意 `MYSQL_HOST` 不要带端口） |
| 首次/空闲后第一个请求偶发 500，日志有 `CynosDB serverless instance is resuming` | MySQL 自动暂停被触发。建议关闭「自动暂停」；已设 `initialization-fail-timeout=-1` 保证容器能起来 |
| 小程序报 `Cloud API isn't enabled` 或 callContainer 失败 | `wx.cloud.init()` 未执行（检查 `app.js`）；`CLOUD_ENV_ID`/`X-WX-SERVICE` 填错；基础库最低版本 <2.23.0 |
| 小程序真机上用默认公网域名请求失败 | 预期行为：默认公网域名不能作为正式调用入口，请走 `callContainer` 或绑定已备案自定义域名 |
| 请求体超 100KB / 响应超 1MB 失败 | `callContainer` 的硬限制。本项目接口分页返回，正常不触发；不要用它上传大文件 |
| 中文日志乱码 | 已在镜像里通过 `LANG=C.UTF-8` + `-Dfile.encoding=UTF-8` 修掉；若自改 Dockerfile 需保留 |
| 改了词库数据但小程序还是旧数据 | 进程内缓存未过期。重新发布版本即可刷新 |
| 健康检查显示 DOWN（若你配了健康检查路径） | 默认健康检查包含数据库状态；MySQL 暂停/不可用时会 DOWN，属预期。可把「自动暂停」关掉 |
| 想省费用 | 副本数最小值设 0（有冷启动），MySQL 开自动暂停（有冷启动报错），流量走内网不花钱 |
| 想部署 Redis / 自己的 MySQL | 不支持。云托管不允许部署有状态服务；用控制台自带 MySQL + 本项目已内置的进程内缓存 |
